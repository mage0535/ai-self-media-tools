# 抖音宠物搬运工作流复盘：刀马猫咪视频

日期：2026-09-16  
范围：热点选择、音乐路由、素材筛选、字幕处理、预览门禁、完整去重、交付状态

## 结论

本次最终成片可观看，但生产过程暴露出四个系统缺口：音乐路由顺序错误、素材发现关键词过宽、原片烧录字幕处理缺少预览门禁、搬运流程未执行完整去重。后续必须把这些检查放在全片渲染之前，并以 fail-closed 状态阻断。

## 发生的问题

1. “萌宠版刀马刀马”属于指定原声热点，却先进入通用真人乐器 BGM 搜索。
2. 初期用 dance/catdance 等字面关键词寻找“跳舞猫”，召回 AI、卡通、摆拍和搬运污染素材；正确需求其实是可映射节拍的真实自然动作。
3. 源片只有烧录英文字幕版本，首版用横贯中下部的模糊带遮挡，虽隐藏英文却遮住猫咪身体，影响观看。
4. 输出经过重新编码、替换音乐和中文字幕本地化，SHA-256 已变化，但未查询账号历史、未计算感知哈希和音频指纹，不能称为完整去重。
5. 手工生成 manifest 状态不能代替可信门禁；最终结论必须绑定真实 MP4 哈希和检查器证据。

## 正确流程

### 1. 热点与音乐路由

- 先判断热点是否属于指定原声、动作、文案模板或普通主题。
- 指定原声热点按“官方绑定原声 → 平台同款高频原声 → 授权替代 → 通用 BGM”排序。
- 在素材搜索前记录话题、music_id、曲目版本、时长、重拍、循环点、发布端绑定方式和权利状态。
- 先拆音乐节奏，再定义需要的动作，最后搜索素材。

### 2. 素材与真实性

- 宠物赛道优先真实视频；排除 AI、卡通、拟人摆拍、抓爪强制动作、合集和明显水印搬运。
- 搜索自然动作：潜行、靠近、抬爪、转头、扑击、停顿、后退，而不是把热点名称当字面动作关键词。
- 至少抽取开头、中段、结尾及动作关键点，确认主体、动作链和安全区。

### 3. 原字幕和水印预检

- 每 1 秒抽帧，并补充转身、伸爪、跳跃等关键动作帧。
- 标记脸部、身体、四肢、尾巴和前后 0.5 秒运动轨迹 ROI。
- 处理优先级：保留原画 → 新字幕放空白安全区 → 最小文字像素处理 → 逐帧修补。
- 禁止横贯画面的大面积模糊、马赛克或色块；无法无损移除时宁可保留原字幕。
- 所有高风险处理先生成 3–5 秒预览并正常速度播放验收，通过后才能渲染全片。

### 4. 搬运视频完整去重

渲染前必须生成 `dedup_evidence.json`，覆盖：

- 源平台、content ID、canonical URL、作者和源 SHA-256；
- 目标账号历史作品、近期交付作品、待发布队列和候选池；
- 关键帧 pHash、镜头级最大相似度、视频指纹和音频指纹；
- 实质性重构：镜头组织、节奏、字幕叙事、音乐结构、独立封面；
- 来源与权利状态；
- 最终 MP4 SHA-256 绑定和程序计算的 passed/failures。

以下不算完整去重：仅重编码、换容器、改 metadata、换音轨、微调亮度、机械镜像、随机旋转或轻微变速。

质量优先：不得用镜像带字幕画面、异常变速、过度裁切、主体遮挡、大面积模糊破坏观看体验。去重用于防止自身重复发布并证明实质二创，不等于版权许可。

### 5. 生产状态机

`CREATED → INPUT_LOCKED → ROUTE_VALIDATED → DEDUP_VALIDATED → PREVIEW_RENDERED → PREVIEW_APPROVED → FINAL_RENDERED → FINAL_VISUAL_REVIEWED → VERIFIED → DELIVERY_PENDING → DELIVERED`

异常状态：`BLOCKED | BLOCKED_DEDUP | REJECTED | FAILED | INTERRUPTED`。

音乐、素材、字幕位置、遮罩、时长、剪辑结构或输出文件发生变化时，创建新 revision，并使旧预览审批和最终目视证据失效。

### 6. 最终验收

- 检查最终交付 MP4，而不是中间文件。
- ffprobe 验证时长、分辨率、编码、像素格式、音轨、采样率和声道。
- 每 2 秒抽帧，并对处理区间按更高帧率复查。
- 正常速度完整播放，检查主体、字幕、黑帧、跳帧、循环接缝、音画同步和片尾。
- 人工目视记录绑定最终 MP4 SHA-256；重编码或替换后旧结论失效。
- Manifest 只作为证据索引，不能自证通过，禁止手工修改 passed。
